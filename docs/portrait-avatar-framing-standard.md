# D LEAGUE｜人物圓形頭像統一裁切與驗收規範

適用範圍：2026/27 球隊名單 48px、手機球員／隊職員頁 104px、電腦頁 160px；後續新增球隊也使用相同標準。不得因裁切驗收改變歷史賽季、全站 UI 或其他隊伍的已確認配置。

## 必須同時滿足的規則

1. **圖片不得超出圓形邊框**：照片外層必須是正方形、圓形且設定 `overflow: hidden`（或 `clip`）；`object-fit: cover`。不只圖片 DOM 有載入，實際 CSS `transform` 之後仍必須覆蓋整個圓形，不得在圓圈內出現露白／底色。
2. **人物頭部完整**：頭頂（包括頭髮、帽子）與下巴不能被意外裁斷，眼睛與鼻子落在主要視覺區域；頭部不緊貼邊界。具體間距依原圖角度判斷，不用硬性百分比取代目視。
3. **人物大小合理**：48px 仍可辨識臉部；104px 可清楚辨識臉和髮型；160px 不應只顯示背景。半身／全身照可適度放大，但不能因此截掉髮頂、下巴或造成露白。
4. **只調必要的人**：預設 `object-position: 50% 50%`、等比例顯示。放大、上下、左右移動屬逐張例外；不以照片寬高比自動移位，不對全隊套一組縮放。不應因「越大越好」而犧牲真實構圖。
5. **橫向拉伸例外**：原始 Excel 已證實橫向壓縮的情況，才考慮 `scaleX`，須與原始顯示效果比對。不得任意將人臉拉寬。
6. **原圖優先於強行放大**：先比對 Excel 內嵌原圖與網站圖；如 Excel 版本清楚且人物相同則換原圖；若原圖已模糊、遠景、人數多、對焦不準或遮擋，歸類「需補照」，不能宣稱靠 CSS 修復。
7. **真實路由必查**：同一張人物照片同時打開球隊名單、球員個人頁、隊職員個人頁（如有）。至少檢查 390px／1280px，並保存 48px／104px／160px 原始截圖。原圖 + 小圓 + 大圓逐人排列以供目視。
8. **一隊一份結論**：明列「已檢查人物／實際修改／原圖限制／需補照／頁面 QA／TypeScript／Build／CI／預覽」。沒有通過的環節標示未完成，不得用圖片載入成功代表視覺驗收成功。

## 共用自動化規則與限制

- 所有新一輪人物 QA 可以使用 `scripts/portrait-circle-coverage.mjs`；它解析實際瀏覽器 `matrix(...)`、取樣圓形內側 720 個邊界點，容忍最多 0.5% 的取樣點缺乏圖片覆蓋。
- 任何明顯越界、露白、圖片外層沒有裁切、非圓形、圖片無法解碼、錯誤人物、來源無效，皆為 **QA 失敗**。
- 此數學檢查**不能辨識人臉、清晰度、五官變形或圖片是否適合**；必須另以實際截圖逐張目視驗收。
- 自動化不會擅自改全站圖片比例，所有 `config/avatarImagePosition.ts` 調整都應逐人指定及回歸測試。
- 新增球隊的 QA 必須匯入同一共用檢查器，不得複製一份不一致的邏輯。
